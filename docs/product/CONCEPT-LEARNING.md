# 개념을 이해하고 다시 사용할 수 있게 만드는 연구 노트북

상태: 제품 명세. 아래 동작·API·수용 기준은 구현 요구사항이며 현재 앱에서 모두 동작한다고 주장하지 않는다.
조사일: 2026-10-18. 공식 공개 페이지와 도움말을 읽었다. 로그인한 서비스의 실제 UI, 유료 기능, 분석 정확도와 처리 시간은 직접 시험하지 않았다. 서비스의 마케팅 성능 수치는 제품 보증으로 채택하지 않는다.

## 사용자가 달성할 작업

사용자가 `latent action이 무엇인지 이해하고, 내가 읽는 논문들이 각각 어떻게 쓰는지 비교하고 싶다`고 입력하면 개념 노트 하나를 열고, 의미 구분 → 선행 개념 → 식과 코드 → 논문 비교 → 연결 근거 → 자기 설명 → 개인 노트 순서로 탐색한다. 긴 자동 요약을 읽는 것으로 완료 처리하지 않는다. 사용자가 자기 말로 설명하고 원문·코드 근거로 돌아갈 수 있는 상태를 목표로 한다.

`latent action`에 관한 구체적 정의·논문 분류·수학식은 별도 논문 조사 결과를 받아야 한다. 이 문서는 특정 논문이 어떤 종류의 latent action을 사용한다고 단정하지 않는다.

## 화면과 탐색 계약

데스크톱 화면은 `개념 목록 / 현재 설명 / 근거·대화` 3영역으로 구성한다. 기본 제목은 `Latent action`이며 큰 영문 슬로건·숫자 장식·완료율 점수를 넣지 않는다. 상단에는 현재 의미 범위, 선택 논문 수, 마지막 근거 갱신일, 검색만 둔다. 노트와 원문을 번갈아 볼 때 탭·스크롤·선택한 문장을 유지한다.

중앙 상단의 짧은 단계 탐색은 `의미 · 기초 · 식/코드 · 비교 · 연결 · 내 설명`이다. 단계는 강제 마법사가 아니다. 이미 이해한 부분은 건너뛸 수 있고 이전 결과를 지우지 않는다. 모바일/태블릿에서는 한 영역씩 표시하고 근거는 drawer로 연다. 키보드 탐색 순서와 현재 선택 표시를 제공한다.

### 1. 질문을 범위로 바꾸기

- 수집함에 용어, 질문, 논문 URL 또는 PDF를 넣으면 기존 개념 ID와 alias부터 조회한다. 이름만 비슷하다는 이유로 기존 개념을 병합하지 않는다.
- 기존 논문에서 이 용어가 등장하는 구절을 먼저 보여준다. 자료가 없으면 `내 라이브러리에서 확인한 정의 없음`과 조사 시작 버튼을 표시한다.
- 질문과 검색 범위(현재 논문 / 내 라이브러리 / 공개 자료)를 눈에 보이게 유지한다. 검색을 열었다는 이유만으로 외부 AI 분석을 시작하지 않는다.
- 조사 완료 시 새 논문은 관련 자료 목록에 제안한다. 라이브러리에 자동으로 수백 개를 저장하거나 과거 후보 목록을 되살리지 않는다.
- 논문 추가와 개념 노트 연결은 개별 선택 또는 명시적 일괄 저장으로 처리한다. 동일 DOI/arXiv/version/content hash는 중복 저장하지 않는다.

### 2. 동일 용어의 정의를 분리하기

각 `sense`에는 짧은 정의, 적용 논문, 원문 정확 구절, 무엇을 입력받고 무엇을 표현하는지, 학습 목표, 추론 시 사용 여부를 기록한다. 정의가 문헌마다 다르면 여러 sense를 유지한다. 저자의 직접 정의와 검토자의 해석을 구분한다.

첫 화면에서는 한 sense를 선택해 `한 문장 설명 → 이 논문에서의 역할 → 다른 뜻과의 차이`를 읽는다. 원문이 없으면 해당 필드를 `확인 불가`로 남긴다. 쉬운 설명은 원문 용어·가정을 삭제하지 않고 펼치기 수준만 조절한다.

### 3. 선행 개념을 필요한 만큼 열기

선행 개념 연결은 `A를 이해하는 데 B가 필요한 이유`라는 설명과 원문/수식 근거를 가진다. 동일 문서에 등장한다는 이유만으로 prerequisite edge를 만들지 않는다. 사용자는 `알고 있음 / 잠깐 보기 / 아직 어려움`을 직접 표시한다.

`잠깐 보기`는 현재 설명 옆에서 정의·작은 유도·다시 돌아가기만 보여준다. 선행 개념을 열어 원래 latent-action 노트의 위치를 잃지 않게 한다. 순환 연결이 있어도 무한 펼침을 하지 않으며 이미 열린 개념으로 이동한다.

### 4. 수식과 실제 코드 연결

| 필드 | 필수 동작 |
| --- | --- |
| 식 | 원문 식 번호·정확 기호·정의역·축·가정을 함께 표시한다. |
| 유도 | 한 행에 한 변환. 사용한 항등식·독립성·근사 여부와 생략한 항을 표시한다. |
| 코드 | repository, immutable commit, config, 파일·행 범위를 표시한다. 인접 구현이나 다른 모델 설정을 섞지 않는다. |
| tensor trace | 입력 → 축 이동/투영/결합/축약 → 출력. 알려진 차원은 설정 근거, runtime 값은 기호로 표시한다. |
| 학습/추론 | 정답·미래 관측·gradient·loss가 언제 존재하는지 표시한다. 추론에 학습 전용 문맥을 남기지 않는다. |
| 시각화 | 선택 연산 하나의 actual shape 도식을 재생한다. 표시용 블록 압축·정적 코드 추적·실제 실행을 각각 명시한다. |

구현이 없거나 코드를 확보하지 못한 논문도 읽을 수 있어야 한다. 이 경우 수식 설명만 제공하고 `코드 확인 불가`를 표시한다. 이미지·영상·예시 숫자를 실제 실험 결과처럼 제시하지 않는다. Manim은 고정 Scene과 검증한 JSON 데이터로 생성하며 생성 코드 실행은 하지 않는다.

### 5. 논문별 비교표

행은 논문, 열은 질문에서 선택한 항목이다. 초기 열은 `정의 sense / 학습 입력 / 목표 / latent의 의미·차원 / 추론 역할 / supervision / 평가 근거 / 구현`으로 한다. 넓은 표는 고정 논문 열과 수평 스크롤로 읽으며 셀은 2줄 요약 후 펼친다.

셀을 누르면 정확 구절·식·표 번호·코드가 오른쪽에 열린다. 수치 비교는 dataset, metric, split, 표준편차 또는 반복 여부를 함께 보며 실험 조건이 다르면 순위를 만들지 않는다. `없음`, `보고 안 됨`, `확보하지 못함`, `해당 없음`을 구분한다. AI의 추정으로 빈 셀을 채우지 않는다.

### 6. 관계 종류가 보이는 그래프

| edge type | 방향·의미 | 생성 근거 |
| --- | --- | --- |
| `cites` | 논문 A → 논문 B | A 참고문헌에 B 식별자 또는 검증한 인용 항목 존재 |
| `adopts` | 구현/논문 A → 기술 B | 실제 코드 import·checkpoint·명시적 방법 채택 구절. 단순 인용만으로 생성 금지 |
| `similar` | 무방향 | 비교 방법·모델/버전·점수 출처. 의미적 유사도를 직접 인용으로 표시 금지 |
| `uses_sense` | 논문 → 개념 sense | 해당 정의를 사용하는 구절 |
| `requires` | 개념 sense → 선행 개념 | 왜 필요한지와 식/설명 근거 |
| `contrasts` | sense 또는 주장 간 비교 | 비교한 항목과 양쪽 근거 |
| `annotates` | 사용자 메모 → 문장/식/개념 | 사용자 명시 연결 |

기본은 선택 개념의 1-hop, 최대 30노드. 실제 채택/인용은 화살표, 유사도는 점선, 미확인 연결은 기본 숨김으로 한다. 색만으로 종류를 구분하지 않는다. `더 보기`에서 확장할 수 있으나 폴링마다 전체 layout을 다시 만들지 않는다. 노드를 누르면 논문·코드·개념 노트를 동일 패널에서 열고 edge를 누르면 연결 이유와 출처를 보여준다.

### 7. 자기 설명으로 이해 확인

질문은 현재 sense와 근거 구간에 연결한다. 기본은 세 종류이며 정답을 먼저 노출하지 않는다.

1. 정의: `이 논문에서 latent가 표현하는 것을 자신의 말로 설명하세요.`
2. 구분: `비교 중인 두 논문에서 같은 용어의 의미가 어디에서 달라지나요?`
3. 적용: `선택한 연산의 입력 축을 바꾸면 무엇이 유지되고 무엇을 다시 확인해야 하나요?`

사용자의 입력은 즉시 개인 draft로 저장한다. `해설 보기`를 누르면 모범 문장 하나 대신 확인할 핵심 조건·누락 항목·근거를 제시한다. AI 평가는 제안이며 자동으로 숙련 완료 판정을 하지 않는다. 사용자가 `이해함 / 다시 확인 / 질문 남김`을 정한다. 답하지 않은 항목을 오답으로 기록하지 않는다.

### 8. 메모와 복습

개인 노트는 생성 설명과 별도 revision을 가진다. 재분석은 생성 영역만 갱신하고 노트·하이라이트·이전 답변을 덮어쓰지 않는다. `[[concept:id|label]]`, `[[paper:id|label]]`와 sentence/equation anchor를 사용한다. source revision이 달라져 anchor가 맞지 않으면 미연결 상태를 표시하고 이전 구절을 보존한다.

복습은 사용자가 선택한 질문만 등록한다. 초기 제품은 `나중에 / 날짜 지정 / 다시 확인`과 최근 답변 이력으로 시작한다. 검증된 스케줄러를 넣기 전 학습과학 기반 최적화나 예상 기억 확률을 표시하지 않는다. 새로운 AI 설명이 생겨도 자동으로 수십 개 카드를 추가하지 않는다.

## 저장 계약과 증거 경계

아래는 논리 모델 제안이며 기존 DB 컬럼 이름을 단정하지 않는다.

- `Concept`: stable ID, name, aliases, user_note_revision.
- `Sense`: concept ID, label, definition, scope, paper IDs, evidence IDs, verification.
- `Evidence`: paper ID/version/hash, source kind, block/sentence/equation ID, UTF-16 range 및 exact quote, 또는 repository/commit/path/line range. 원문과 코드의 anchor 표현을 혼용하지 않는다.
- `Claim`: sense ID, text, author_claim / derived / illustrative / unknown, evidence IDs, generation revision.
- `Relation`: source ID/type, target ID/type, relation type, directed, evidence IDs, origin(user/source/model), verification. 같은 두 노드에도 관계 종류별 여러 edge 허용.
- `LearningAttempt`: question ID/version, user answer, revealed timestamp, self assessment. 생성 해설과 분리 저장.
- `ReviewItem`: opt-in question ID, due date, suspended, attempt IDs. 사용자 노트 삭제와 연동한 암묵적 삭제 금지.

외부로 전송하는 내용과 로컬 저장 내용을 구분한다. 비공개 노트·라이브러리 전체를 묵시적으로 검색 제공자에 보내지 않는다. 모델 입력은 선택한 자료와 현재 질문으로 제한한다. 분석 결과의 링크·문자열은 untrusted 데이터로 처리한다.

## 비동기 동작·실패 처리

진행률은 실제 완료 단위로 계산한다. 예: 원문 확인 `3/5`, 비교 셀 검토 `12/24`, 그래프 연결 검증 `8/10`. 전체 분모가 정해지지 않은 검색은 처리중 표시만 사용하고 가짜 87%를 만들지 않는다. source 수집 실패는 부분 결과와 미확인 영역을 남긴다. 대기열은 취소·재시도 가능하고 동일 요청의 동시 실행은 중복 저장하지 않는다.

재방문 시 이전 결과부터 보여주고 새 evidence revision의 차이만 확인하게 한다. 노트 편집 중 background 결과가 도착해도 input·cursor·scroll을 보존한다. 그래프·Manim·전체 재분석은 명시적으로 열거나 실행할 때만 작업한다. 사용자의 복습 설정 없이 알림을 만들지 않는다.

## 수용 기준

1. 동일 용어를 다른 뜻으로 쓰는 두 논문 fixture를 입력했을 때 sense가 자동 병합되지 않고 각 구절로 돌아갈 수 있다.
2. evidence가 없는 비교 셀은 `확인 불가`이며 모델이 만든 문장을 원문 quote로 저장하지 않는다.
3. 그래프의 유사 edge는 citation/adopts와 다른 의미·표시·필터를 갖는다. 실제 채택 출처가 없으면 adopts 생성 불가다.
4. 정의 문장·수식·코드·사용자 메모에서 개념 노트로 이동한 뒤 원래 위치로 돌아간다.
5. 실제 shape trace에서 학습 입력과 추론 입력의 차이가 표시되며 설정 미확정 값을 임의 숫자로 채우지 않는다.
6. 자기 설명 질문은 답변 공개 전 입력할 수 있고, 저장 후 reload·재분석에도 개인 답변이 유지된다.
7. source revision 변경 후 위치가 어긋난 하이라이트는 새 문장에 조용히 붙지 않는다.
8. 500개 개념·5,000개 관계 fixture에서도 최초 화면은 bounded 1-hop만 조회하고 전체 그래프 렌더를 자동 실행하지 않는다. 실제 성능 수치는 측정 후 기록한다.
9. 400px 화면과 다크모드에서 근거·비교·질문 controls에 키보드 접근이 가능하며 긴 논문 제목이 화면 폭을 늘리지 않는다.

## 구현 순서

P0: sense와 evidence 분리, 비교 셀 출처, typed graph, 개인 노트 보존, 선택 자료 범위 표시.
P1: 선행 개념 drawer, 수식/actual-code trace 연동, 자기 설명과 시도 이력, 명시적 복습 등록.
P2: 검증된 복습 스케줄러, 새로운 후속 논문과 기존 주장 차이 검토, 선택 연산 시각화 확대.

외부 서비스와의 자동 연동·계정 연결은 이번 명세의 전제 조건이 아니다. 조사한 UX 원칙을 로컬 라이브러리와 출처 기반 학습 작업에 적용한다.

## 2026-10-18 구현 범위

개념 학습 UI의 개념·논문 비교·관계 그래프·확인 질문, 개인 답변 저장과 노트 내보내기를 구현했다. `latent-action.json`에는 LAPA/Genie/UniVLA의 출처 기반 학습 자료가 포함된다. 다른 개념은 `/api/concept/study/generate`로 같은 구조의 자료를 생성한다. 실제 API는 GET `/api/concept/study/{id}`, POST `/api/concept/study/generate`, POST `/api/concept/study/progress`다. 답변은 사용자 확인 기록이며 자동 채점·숙련도 점수가 아니다. 간격 반복 일정, 새로운 개념용 Manim 장면 자동 생성, 외부 서비스 계정 연동은 이번 구현에 포함되지 않는다.

질문 본문·참고 답안의 SHA256 revision을 개인 답변에 저장한다. 재생성으로 질문이 바뀌면 이전 답변과 질문 기록을 보존하고 ‘이해함’을 해제한다. 이전 화면의 지연 저장은 revision 불일치로 거부한다. 작업 취소는 오류로 바꾸지 않으며 기존 학습 자료를 유지한다.
