# Automatic concept learning: ACT

Source: [Learning Fine-Grained Bimanual Manipulation with Low-Cost Hardware](https://arxiv.org/abs/2304.13705), official [project and code links](https://tonyzhaozh.github.io/aloha/). Tested on 2026-10-18.

The paper was actually imported through the normal arXiv metadata/source path. Concept guides were generated by the installed Codex CLI from the collected original text; no ACT-specific canned guide was added to the repository. The source-first concept stage runs independently of the full brief/tensor audit.

## Stored results

- Action Chunking:4 explanation sections,3 self-explanation questions,2 exact source quotations.
- Conditional Variational Autoencoder:4 sections,3 questions,2 exact source quotations.
- Temporal Ensembling:4 sections,3 questions,2 exact source quotations.
- Existing Closed-loop Control notebook:prerequisite relation, with reason and an exact ACT quotation.
- Local graph:6 nodes and5 edges. The existing DreamZero association is a library membership edge marked original-source-unverified; it is not an ACT citation or adoption claim.
- Existing personal notes, annotation links and study answers had identical hashes before and after the concept job. Hashes and personal records are not published.

The initial generated payload used an unsupported descriptive concept title. Validation rejected it without writing partial notebooks. The generic repair path reused that failed draft and corrected it to an actual original term, then reran quote/schema/relationship validation before transaction commit. This behavior is covered by regression tests, including a failed second repair preserving existing notes.

## Scope

Quoted passages are checked against collected paper text. Code explanations are static source analysis, not executed training or reproduced experiments. The guides distinguish paper dimensions, current public code settings, and unavailable runtime values. The current pass produces up to4 central concepts, not an exhaustive glossary. Generated content still requires research judgment.

Native application verification uses a local sanitized snapshot of these actual generated results, without personal notes, annotations or answers. The snapshot and screenshots are ignored work artifacts; no personal database or model logs are committed.

The packaged Electron app opened the actual results, expanded source passages, followed graph/notebook links, and displayed generated explanations, the paper comparison,9 questions and per-paper backlinks without JavaScript errors. The full brief/tensor audit is tracked separately from this concept-stage verification.
